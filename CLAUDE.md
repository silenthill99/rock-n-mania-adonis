# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

AdonisJS 7 + Inertia (React 19) app. MySQL via Lucid ORM. Uses `node ace` (the AdonisJS CLI) and `@japa/runner` for tests.

## Commands

- `npm run dev` — start dev server with HMR (`node ace serve --hmr`)
- `npm run build` — production build
- `npm run test` — run the full Japa test suite (`node ace test`)
- `node ace test --files="tests/unit/some.spec.ts"` — run a single test file
- `node ace test unit` / `node ace test functional` / `node ace test browser` — run one suite (see `adonisrc.ts` for suite definitions and timeouts)
- `npm run lint` — ESLint (`@adonisjs/eslint-config` + React rules)
- `npm run format` — Prettier (`@adonisjs/prettier-config`)
- `npm run typecheck` — typechecks both the backend (`tsconfig.json`) and the Inertia frontend (`inertia/tsconfig.json`) separately; run both when touching either side
- `node ace migration:run` / `node ace migration:rollback` — run/rollback DB migrations (also regenerates `database/schema.ts`, see below)
- `node ace make:controller|make:model|make:migration|make:validator` — scaffolding, follow existing naming (snake_case files, e.g. `new_account_controller.ts`)

No git repository is initialized in this working directory yet.

## Architecture

### Generated code — do not hand-edit

Several files/directories are regenerated by Adonis tooling and are marked "DO NOT EDIT manually" in their header. Never edit these directly; change the source they're generated from instead:

- **`database/schema.ts`** — base Lucid model classes (one `<Name>Schema` class per table/pivot, with typed `@column` declarations) generated from the migrations in `database/migrations/`. Regenerated by `node ace migration:run`/`rollback`. Real models in `app/models/*.ts` extend these generated `*Schema` classes and add relations/getters (e.g. `export default class Album extends AlbumSchema { @manyToMany(...) ... }`). Column-level generation behavior (nullability, types, etc.) can be tuned per-table in `database/schema_rules.ts`.
- **`.adonisjs/server/*`** (`controllers.ts`, `routes.ts`, `pages.d.ts`, `events.ts`, `listeners.ts`) and **`.adonisjs/client/*`** (Tuyau `registry/*`, `manifest.d.ts`, `data.d.ts`) — generated by the `indexEntities`, `indexPages`, and `generateRegistry` hooks wired in `adonisrc.ts`, and refreshed automatically by the dev server/build. `start/routes.ts` imports controllers via `#generated/controllers` (not direct relative imports) so new controllers show up there automatically once a route references them.
- Inertia shared-prop/flash types in `inertia/types.ts` are inferred from `@generated/data`, which flows from controller `inertia.render()` calls and the inertia middleware — add new shared props on the backend side, not by hand-editing frontend types.

### Backend

- **Models** (`app/models/`): thin subclasses of the generated `*Schema` base classes, adding only relations and computed accessors. `User` composes `withAuthFinder(hash)` for auth (`User.verifyCredentials`, password hashing).
- **Auth**: session-based (`config/auth.ts`, guard `web`). `middleware.guest()` guards signup/login routes, `middleware.auth()` guards everything behind login (see `start/routes.ts`). `silent_auth_middleware` runs globally to populate `auth` without forcing a login.
- **Validation**: VineJS validators in `app/validators/`, used via `request.validateUsing(...)` in controllers. Date fields use a global Luxon transform registered in `start/validator.ts` (VineJS `date()` → `DateTime`, not JS `Date`).
- **Controllers**: one responsibility per method, thin — validate, call the model, redirect or render Inertia (`inertia.render('page/name', props)`). No service layer currently exists; business logic currently lives in controllers/models.
- **API responses**: `providers/api_provider.ts` adds `ctx.serialize(data)` / `ctx.serialize.withoutWrapping(data)` to `HttpContext`, wrapping JSON in `{ data: ... }` and handling Lucid pagination metadata consistently. Use transformers in `app/transformers/` (`BaseTransformer` subclasses with a `toObject()` picking allowed fields) when shaping model data for the client, as `UserTransformer` does.
- **Routing**: `start/routes.ts` is the single source of truth for routes; named routes (`.as('name')`) are used for redirects (`response.redirect().toRoute(...)`) and are also what both the Tuyau client and Inertia's `<Form route="...">` reference on the frontend.

### Frontend (Inertia + React)

- Pages live in `inertia/pages/`, path mirrors the string passed to `inertia.render()` (e.g. `inertia.render('auth/login', ...)` → `inertia/pages/auth/login.tsx`). Layouts live in `inertia/layouts/` (`app.tsx` for authenticated pages, `marketing.tsx`/`auth.tsx` for public pages).
- `usePage().props` and flash messages are globally typed through `inertia/types.ts` (`InertiaProps<T>`), sourced from the backend-generated `@generated/data` — don't redeclare these types locally in pages.
- Typed API/route access on the client goes through **Tuyau** (`@tuyau/core`, client configured in `inertia/client.ts`, wrapped around the app via `TuyauProvider` in `inertia/app.tsx`). Prefer Tuyau/`<Form route="...">` + named routes over hand-written URL strings.
- Path alias `~/*` maps to `inertia/*` (see `inertia/tsconfig.json`); use it instead of relative `../../` imports within the frontend.
- Styling: Tailwind v4 + DaisyUI, dark/light via `ThemeToggle`/`theme_toggle.tsx`; icons from `lucide-react`.
- SSR is scaffolded (`inertia/ssr.tsx`, entrypoint configured in `config/inertia.ts`) but currently disabled (`ssr.enabled: false`).

### Domain model

Core entities: `User` (has many `Album`, `Clip`), `Album` (belongs to `User`, many-to-many `Artist`), `Artist` (many-to-many `Album`), `Clip` (belongs to `User`). Some scaffolding exists ahead of full wiring — e.g. `app/validators/artist.ts` and `app/validators/clip.ts` are still empty stubs, and `AlbumsController.store` is not yet registered in `start/routes.ts`.
